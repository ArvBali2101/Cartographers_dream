# Merged game learnings

- Inspect remote-tracking branches, not only local HEAD, when the user refers to a teammate merge. friend/main and main can contain fundamentally different games even when both are present in the same repository.
- Preserve the actual authored visual pipeline rather than approximating it in another renderer. This build depends on its own assets, theme, fonts, cave meshes and procedural map code.
- Asset imports must finish before runtime verification. Shipping source without its .godot cache requires a proper first import.
- Enrich existing readable logs, pages and interludes without importing contradictory gates or chapter counts from an unrelated prototype.
- Use isolated test save paths. A scene-loading smoke suite is not a completed-game playtest or proof of balanced difficulty.

- HD means verified source resolution and an inspected in-engine result, not a larger screenshot of a low-resolution background. Use OpenGL normal maps, roughness and anisotropic filtering without switching away from the teammate's visual pipeline.
- Expanded lore needs expanded reading time and bounded text blocks; adding prose to a fixed 4.5-second overlay is not usable storytelling.
- Update a generated file's source generator too. Preserve mechanics while exposing lore through existing objects and optional evidence.
- Active-monster route bots verify progression, not emotional pacing, human difficulty or performance on every machine.

- Naming gods can clarify the escalation without identifying every monster or removing uncertainty. Keep investigator theories distinct from primary-source facts; do not casually classify Cthulhu as an Outer God.
- A 1080p render of primitive geometry is not a realistic character. Inspect close-ups, use appropriately licensed detailed assets, and disclose whether animation is camera/mesh motion or a true skeletal performance.
- Godot child Controls can begin with zero size. Explicit stage sizing and screenshots caught an initially invisible vignette; size assertions alone were added afterward.
- Renderer automation can consume the user's physical keystrokes. Isolate story-test input and test the full ending, not only component instantiation.
- Extend the existing mixer and volume controls; avoid overwriting the soundtrack that the user prefers. Peak/RMS checks are useful but do not replace listening on real playback hardware.



- Attachment code is a reference, not authority to overwrite the entire working game. A partial ZIP can contain the desired cutscene without containing levels or project settings.
- Lore can be evidence encountered during mandatory actions instead of lecture-style cutscenes. Clearly distinguish in-game abbey beliefs from literary canon.
- A callback assertion does not prove a player can reach its trigger. Test physical movement through animated gates; transform the AnimatableBody3D directly so the visible hinge and collider agree.
- When image generation is rate-limited, disclose it and use a suitable licensed asset path without claiming a successful photoreal edit. A live rendered stone idol is not a rigged organic god.

- Restoring a supplied asynchronous cutscene also requires scene-removal cancellation. A stale film coroutine must not start gameplay after a chapter/interlude has replaced its scene; guard both before and after awaits.
- In first-person games, a paper reader must release the captured cursor, pause simulation and timing, and offer an explicit close control. Put its UI above the HUD and retain keyboard dismissal. Test actual mouse clicks, repeated reads and restoring prior pause state.
- Submission cleanup must preserve original media and dirty legacy source in a recoverable archive. Exclude engines, import caches and large editing masters from the source push; moving Resolve media may require relinking absolute paths.
